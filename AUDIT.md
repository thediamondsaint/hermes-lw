# Hermes LW audit and implementation notes

Second-pass audit of the local Quickshell client and its Python bridge. The GitHub projects below were reviewed for working patterns; the notes describe what Hermes LW adopted or adapted. These links are references, not copied code.

| # | Audit finding | GitHub reference and pattern | Implemented in Hermes LW |
|---:|---|---|---|
| 1 | A process interruption during settings writes could leave corrupt state. | [Kanri](https://github.com/kanriapp/kanri) keeps its offline board in a human-readable local JSON file. | App settings, estimates, cache, profile files, and exports now use atomic replacement. |
| 2 | Simultaneous writes shared predictable temporary names. | [KanbanQube](https://github.com/mathiasconradt/kanbanqube) uses separate per-object files to reduce write collisions. | Temp file names include process and thread IDs; cleanup runs after both success and failure. |
| 3 | Exported project data could inherit permissive default file permissions. | [Hermes Agent](https://github.com/NousResearch/hermes-agent) documents profile-scoped secrets and local-only dashboard assumptions. | Hermes LW data/config writes and project exports use owner-only file mode. |
| 4 | The local API accepted unbounded request bodies. | [Hermes Agent dashboard security](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/web-dashboard.md) uses explicit local trust boundaries and fail-closed behavior. | JSON requests are capped at 1 MiB and API keys at 8 KiB. |
| 5 | Malformed JSON and non-object payloads could produce confusing tracebacks. | [Hermes Kanban](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/kanban.md) keeps the board API aligned with typed task operations. | Invalid JSON, bad lengths, and non-object JSON get concise client errors. |
| 6 | Validation errors and internal failures were reported with the same status. | [Hermes Agent web UI](https://github.com/NousResearch/hermes-agent/blob/main/web/src/pages/ProfilesPage.tsx) surfaces expected profile-fetch failures as recoverable UI states. | Request validation returns 400; unexpected server failures return 500. |
| 7 | Local API responses could be cached or interpreted as other content types. | [Hermes Agent dashboard](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/web-dashboard.md) treats the dashboard as a privileged local control surface. | Responses now set `no-store`, `nosniff`, and an explicit content length. |
| 8 | Prefix route matching could accidentally accept unknown API paths. | [Hermes Agent](https://github.com/NousResearch/hermes-agent) routes model and profile operations through explicit commands and provider APIs. | State and model endpoints require exact paths; profile IDs are parsed from the URL path separately. |
| 9 | A malformed catalog response could replace a valid cache. | [Model Price](https://github.com/xiaobox/model-price) uses a bundled fallback snapshot so catalog browsing survives backend cold starts. | The live OpenRouter payload must have the expected shape and contain usable models before it replaces cache data. |
| 10 | One malformed model row could break the whole catalog. | [OpenRouterList](https://github.com/jvrck/openrouterlist) normalizes model capabilities, pricing, and context for its searchable catalog. | Non-object catalog rows are skipped during normalization. |
| 11 | Catalog refresh failure could leave the loading indicator stuck. | [OpenRouterList](https://github.com/jvrck/openrouterlist) has explicit refresh and filtering states. | Failed requests clear `modelCatalogLoading` and leave the error visible. |
| 12 | Rendering every provider model at once makes a large catalog hard to navigate. | [OpenRouterList](https://github.com/jvrck/openrouterlist) shows a bounded first page with a “Show more” control. | Hermes LW shows 100 results at a time, with incremental “Show next 100” paging. |
| 13 | Price sorting alone does not answer “what will my request cost?” | [AI Pricing Tracker](https://github.com/ComplexVariable/ai-pricing-tracker) compares models using a configurable input/output workload mix. | Users can set sample input and output token counts and see per-model estimated cost. |
| 14 | Broad model lists need task-oriented discovery. | [AI Models](https://github.com/onurh/ai-models) groups models by output type and tracks modalities and capabilities. | The existing use, modality, capability, publisher, context, and price filters remain independent and composable. |
| 15 | Search results were difficult to scan when a query changed. | [OpenRouterList](https://github.com/jvrck/openrouterlist) combines search with capability, price, and modality filters. | A new query resets the visible page and works with the existing multi-term filters. |
| 16 | Automatic refresh could overwrite an open edit or detail dialog. | [drkpxl/kanban](https://github.com/drkpxl/kanban) refreshes when the user returns to the board rather than interrupting active edits. | Background polling pauses while any modal/editor is open. |
| 17 | Switching projects could leave a task selection/details panel from the previous board. | [Hermes Kanban](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/kanban.md) treats board selection as the scope for subsequent task operations. | Project changes clear selected tasks and close stale task details before loading the next board. |
| 18 | Board cards were mouse-only. | [Kanbo](https://github.com/maxgfr/kanbo) supports keyboard-operable boards and cards. | Cards are tab-focusable, announce title/status/assignee, open with Enter, and select with Space. |
| 19 | Searching the current workspace took several pointer steps. | [Signboard](https://github.com/cdevroe/signboard) provides keyboard shortcuts for search, navigation, and modal dismissal. | Ctrl+F focuses model search in the catalog or task search on the board. |
| 20 | Task titles could be too long for cards and shell commands. | [Portable Kanban](https://github.com/harehare/portable-kanban) keeps task records structured and searchable across its UI and CLI. | Task titles are limited to 200 characters. |
| 21 | Large task descriptions could overload Hermes CLI arguments. | [Kanri](https://github.com/kanriapp/kanri) stores rich card descriptions as board data instead of unrestricted command input. | Task descriptions are limited to 20,000 characters. |
| 22 | Deleted or mistyped profile IDs could silently disappear from assignment rules. | [Hermes Web UI](https://github.com/tangledup-ai/hermes-web-ui) validates profile-aware Kanban assignment against managed profiles. | Unknown profile IDs are rejected for allowed-profile policies instead of silently filtered out. |
| 23 | Priority values outside the UI’s range were accepted by the API. | [Orbit](https://github.com/noveum/orbit) uses bounded issue properties and explicit workflow state. | Task creation validates priority in the supported 0–4 range. |
| 24 | Malformed tag payloads could fail during iteration or be stored inconsistently. | [KanbanQube](https://github.com/mathiasconradt/kanbanqube) represents labels as structured card fields and supports search/filtering. | Tags must be a list or comma-separated text; valid tags remain capped at 12, with 32 characters each. |
| 25 | Custom endpoint URLs and profile personalities had no size/credential guardrails. | [Hermes provider plugin docs](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/model-provider-plugin.md) distinguish endpoint URLs, credentials, and provider-owned authentication. | Custom URLs reject embedded credentials/query strings/fragments; profile personality and credentials have explicit size limits and atomic writes. |

## Follow-up opportunities

This pass addresses the 25 listed issues. Further work could add drag-and-drop status transitions, a model comparison tray, profile import/export archives, and board event streaming. Those need separate design choices because Hermes CLI remains the source of truth for current task and profile state.

## Live-window correction

The first desktop review exposed a layout issue that static inspection missed: fixed-width catalog filter rows overflowed the 1200×760 Quickshell window, pushing controls offscreen. The catalog now uses compact separate rows. The top toolbar and sidebar **Options** entries now open a distinct app-wide settings page; profile-specific settings remain under **Models & Providers**. The updated catalog screenshot is cropped to the catalog itself so it contains no local profile or board data.
