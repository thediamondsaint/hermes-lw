# Hermes LW audit — 25 October 2026

Reviewed the committed Quickshell UI, Python bridge, startup script, desktop entry,
local state-file permissions, installed Hermes 0.19.0 CLI, and running instances.
The starting tree was clean. The installed desktop entry points directly to this
checkout. No real profile/task/credential was edited by the checks, and no model
request was sent. Desktop checks used synthetic data, initially on workspace 5 and finally on workspace 4 at the user’s request. Audit launches now use a temporary fixture-only workspace 4 rule without switching the user’s active workspace.

## Verified coverage

- Initial trace: 37 literal UI API paths and 112 QML functions. No undefined `root` function call was found; the failures were mostly state, transport, visibility, or backend behavior.
- 24 automated tests pass: backend policies, authoritative advisor metadata, generation isolation, credentials, concurrent state changes, real QML HTTP behavior, and stale/busy backend startup.
- Seven QtTest UI cases pass using actual mouse events and a synthetic backend: Options routing, provider-preserving Refresh, advisor Escape behavior, short-window profile scrolling/visible validation, Ask AI completion, connection-switch protection during generation, and the narrow-tile scroll fallback. The runner also checks the actual Hyprland client is tiled on workspace 4.
- Python compilation and shell syntax pass. QML lint has no parser or missing-property diagnostics; existing unqualified-access warnings remain and should be reduced during component extraction.
- CI runs the automated backend/Qt HTTP/startup tests. The desktop click suite remains a local check because it needs Quickshell, QtTest, and Hyprland.

## Improvements still needed, in priority order

1. **Enforced spend limits.** Dollar values are still planning metadata. A provider-side capped credential or metered gateway with pre-request reservation is required before claiming a hard budget. See [cost enforcement design](docs/cost-enforcement.md). Do not equate a timeout or known token rate with a dollar ceiling.
2. **Native task policy enforcement.** This patch closes the unassigned-dispatch paths through Hermes LW. Other Hermes clients and the gateway can still change tasks directly. The allowlist and budgets need enforcement inside Hermes dispatch or a dedicated controlled execution service, including delegated workers.
3. **Real pause/cancel controls.** The current profile pause affects new assignments through this app. It does not stop a running worker or disable the gateway's already queued work. Add worker run state, reclaim/cancel, and explicit pause scope.
4. **Profile-specific key provisioning and usage.** Add provider-managed capped keys, usage reconciliation, cap remaining, and expired/revoked credential states. Preserve the separation between estimates and enforced limits.
5. **Replace remaining custom button rectangles.** Most lack keyboard focus, Space/Enter activation, accessible names, and visibly disabled states. Introduce a reusable native Button style and migrate by screen, with click and keyboard tests for each flow.
6. **Break up Main.qml and backend.py.** Dialogs, provider catalog, transport, task policy, and profile management need independent components/modules. The extracted HTTP client is a first step; avoid another visual rewrite without behavior tests.
7. **Responsive main-page layouts.** The main canvas still uses a 1150×720 layout behind scrollbars, and catalog filter rows have fixed widths. Replace this fallback with adaptive layouts/flows and test different tile sizes and display scaling. The current scrollbars preserve access, but do not replace a responsive design.
8. **Asynchronous job status.** Generation currently waits on a long HTTP request. Durable job IDs, progress, cancellation, reconnect/recovery, and per-connection pending state would make background work reliable.
9. **Stronger secrets storage.** Profile environment files and gateway tokens have owner-only permissions, but are not OS-keychain encrypted. Full clone and plugin/MCP config need a formal credential inventory and explicit portability rules.
10. **Complete Kanban editing and recovery.** Add title/body editing, dependency removal, attachment controls, run logs, and reclaim/reassign. Preserve lifecycle events; priority is currently updated directly in SQLite because the installed CLI lacks a priority edit command.
11. **Real AI profile-team creation.** AI/Profiles remains local heuristic matching of existing profiles. It does not generate new profiles/personality/model teams. Keep the interface explicit about this until implemented.
12. **Remote integration tests.** Add disposable SSH and HTTPS gateways to validate authentication, tunnel loss, expired tokens, connection switching, and server version mismatch. The current fixture suite verifies client behavior, not a real VPS deployment.
